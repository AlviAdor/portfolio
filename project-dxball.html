Project

DX-Ball: a brick-breaker that outgrew its own prototype.

Modes

Five distinct ways to play

Classic for a balanced run, Speed for risk/reward pressure, Zen for a relaxed survival pace, Rapid Fire for chaos, and Gauntlet, which ramps difficulty continuously the longer you survive.

Systems

Boosts and scoring that matter

Power-ups spawn mid-run (extra life, wider paddle, slower ball, score multipliers, bonus time), each with its own visual tell, plus a combo multiplier that rewards consecutive boost pickups.

Settings

Actually configurable

Ball color, ball radius, paddle speed, sound on/off with a volume slider, boost animation toggle, and a light/dark theme, all persisted between sessions.

What it actually looks like.

Why five modes instead of one

DX-Ball started as the kind of brick-breaker clone everyone builds once (paddle, ball, bricks, done in an afternoon). What kept me coming back to it was the realization that "keep the ball alive" supports a lot more variety than one difficulty curve.

Each mode changes the actual rules, not just a speed multiplier: Zen mode is deliberately forgiving so it's relaxing rather than tense, Rapid Fire leans into frequent hazards for players who want chaos, and Gauntlet is the one built around a continuously ramping difficulty curve so a single run can go from easy to genuinely hard without a level transition.

The settings screen was worth building properly rather than hardcoding defaults. Ball radius and paddle speed sound like minor tuning values, but they change how a mode actually feels to play, and persisting them (along with a best score per mode) was what made it feel like a real small game instead of a script I run once and forget.
