Secure Auth Demo: the app that backs up every claim on the Security pages.

Zero-knowledge

Encrypted contact inbox

Messages are RSA-OAEP + AES-256-GCM encrypted in the visitor's browser with your public key. The server stores only ciphertext. There's no code path that could decrypt it even if I wanted to.

End-to-end

Invite-to-chat

Invite a sender into a private chat; they get temporary credentials, set their own password, and get their own keypair generated client-side. Every message after that is encrypted twice (once per participant) before it leaves the browser.

Hardened

Real account security

Argon2id/bcrypt password hashing, CSRF tokens on every state-changing request, five-strikes rate limiting with lockout, and a CAPTCHA that's enforced server-side, not just hidden in the UI.

Why this exists

The Security section of this site makes specific, checkable claims: rate limiting, parameterized queries, session hardening, encrypted messaging. I got tired of security pages that just assert this stuff in prose with no way to verify it, so I built a real app to back it up instead of writing another paragraph about best practices.

The part I'm most proud of is the contact form: your message is encrypted in your browser with the Web Crypto API before it's ever sent, using a keypair whose private half never leaves local storage, protected by a key derived from my own login password. I can open phpMyAdmin and stare at the raw database rows and see nothing but ciphertext. It only turns back into words in my browser, after I type my password.

From there it extends into an actual end-to-end encrypted chat: I can invite whoever messaged me into a private conversation, and every message is encrypted client-side with a fresh key, specifically for both of us, before the server ever sees it. The server's job is just to store and relay bytes it can't read.

This one is a working app, not a mockup. You can register, log in, and use it right now using the Login link in the navigation.
